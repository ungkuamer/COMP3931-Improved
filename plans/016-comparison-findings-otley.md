# Optimiser vs RL Comparison — Otley, UK (small city)

Implements **OPTIMIZER_SPEC §11 item 6** / §12 DoD: run the full comparison on
one small city, produce the §10 table, and sanity-check that greedy ≥ RL —
or diagnose why not.

- **Instance:** Otley, UK (OSMnx). Bike graph |V|=1422 |E|=3212; walk graph
  |V|=2314 |E|=6254; **132 candidates** shared by every solver and the RL env
  (§8 fairness — derived once via `extract_candidates`).
- **Budget:** 200,000. **Solvers:** greedy, greedy + local search, ILP
  (OR-Tools CP-SAT, coverage-only oracle), MaskablePPO (4096 timesteps, 2 envs).
- **Generated by:** `python scripts/run_comparison.py --city "Otley, UK" ...`
  (the single-command §10 table runner, OPTIMIZER_SPEC §12 DoD).

## Sanity check: does greedy ≥ RL?

**No — in the weighted run, RL (0.1004) beats greedy (0.0584).** Diagnosis:

1. **Greedy stalls at 1 edge.** Greedy-by-marginal-gain-per-cost adds edges
   only while `objective_delta > 0`. With the default weighted objective
   (`0.4·connectivity + 0.4·coverage − 0.2·fragmentation`) the function is
   **non-monotone** on this instance: after the first edge, every affordable
   second edge *decreases* the objective (the fragmentation penalty for an
   isolated new component outweighs its coverage/connectivity gain), so greedy
   stops. Local search cannot escape either — 1-opt swaps of a single edge and
   2-opt exchanges of one edge for two both score worse than the 1-edge seed.
   This is exactly the OPTIMIZER_SPEC §5 caveat: *"if f is not submodular
   (e.g. some fragmentation definitions), the [greedy] guarantee doesn't
   hold."*

2. **Yet a large edge set scores higher.** The ILP's 35-edge solution and RL's
   112-edge solution both score well above the 1-edge greedy solution
   (0.1175 and 0.1004 vs 0.0584). The objective is higher at the top of the
   construction path but non-monotone along the greedy path — greedy is
   trapped in a local optimum of size 1.

3. **Greedy is not broken — the objective is.** Run B proves this: on the
   **coverage-only** objective (monotone submodular), greedy picks 38 edges
   and reaches **99.72% of the ILP optimum (0.28% gap)** — the spec's promised
   `(1−1/e)`-beating behaviour. So the greedy/LS machinery is correct; the
   weighted objective's fragmentation penalty is what breaks monotonicity and
   stalls greedy.

4. **Why RL wins the weighted run.** RL is *not* optimising the canonical
   objective directly — it optimises a shaped reward (continuity bonus, road
   priority, isolation penalty, budget-efficiency; §3.5/§5.5) that encourages
   building a large *connected* network. That shaped reward pushes RL past the
   greedy local optimum; when the resulting 112-edge policy is scored by the
   **shared canonical objective** (§3.2/§8), it lands at 0.1004 — between
   greedy (0.0584) and the ILP ceiling (0.1175). This is the spec's intended
   comparison: RL's number and the optimisers' numbers are directly
   comparable because they are all scored by the same `objective`.

## Recommended next steps (out of scope for item 6)

- **Make the weighted objective monotone / submodular** (e.g. drop the
  fragmentation penalty from the *objective* and keep it only as an RL reward
  shaping term, per §3.2's separation of objective and reward), so greedy
  regains its guarantee on the reported metric. This is the cleanest fix and
  would likely make greedy ≥ RL again.
- **Incremental `objective_delta`** via `MetricsState` (plan 010 deferred the
  full-recompute version). The coverage-only greedy run took 9m41s purely from
  re-`objective`-ing the whole graph per candidate per round; an incremental
  delta would cut this to seconds and let local search run more iterations.
- **Full-objective ILP** (§7) with connectivity via flow/Steiner auxiliaries,
  so the ILP is a true ceiling for the weighted objective too (currently the
  ceiling is only valid for coverage-only weights).
- **Tune RL** (more timesteps, PPO hyperparameters) — a 4096-step PPO is a
  very light training run; the gap to the ILP (14.5%) may close with training.
